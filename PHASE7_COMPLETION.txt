============================================
EXAMPLE USAGE
============================================

Starting Server with Observability:
  set CLUSTER_NODE_ID=node1
  set LOG_LEVEL=INFO
  set LOG_FORMAT=json
  set METRICS_ADDR=:8080
  main.exe

Checking Metrics:
  curl http://localhost:8080/metrics

Health Check:
  curl http://localhost:8080/health

Running Benchmark:
  benchmark.exe -addr localhost:5000 \
                -clients 10 \
                -duration 30 \
                -read 80 \
                -write 15 \
                -delete 5

Viewing Logs:
  (Structured JSON output to stdout)
  Or with file: set LOG_FILE=server.log

PERFORMANCE CHARACTERISTICS
============================================

Metrics Collection:
- Atomic operations for counters (thread-safe)
- Minimal overhead (<1% CPU impact)
- O(1) metric recording
- Sliding window for throughput (60-second window)

HTTP Endpoint:
- Non-blocking (runs in separate goroutine)
- Snapshot-based (no locks during HTTP response)
- JSON encoding for interoperability

Logging:
- Async writes to file
- Minimal formatting overhead
- JSON parsing compatible with log aggregators

Benchmark Tool:
- Realistic concurrent client simulation
- Accurate latency measurement
- Configurable workload mix
- Pre-population for consistent testing
